# Project Final Review and Reflection

## Addressing Relevant Implications

### Accessibility

Throughout the process of making the web app, I made sure to address the Accessibility Implication in multiple aspects, such as design features, layout considerations, and HTML structuring. One design features that I made to address the implication of accessability was to make my web app follow a logical and concise structure. This is evident in the two hemispheres of my web app, the regular user side, and the admin side. In the regular user aspect of the site, you can only go 1 page deep past the homepage, and can always clearly have a way back to the home page. This means people won't be confused by my site, and won't go so far deep that when they need to get back to a specific page, it is always at most 2 clicks away, and very easy to remember. This makes my site accessible, as it means that all types of people with different tech abilities can confidently use my site, and wont be confused by millions of pages. When I was considering the layout of the web app, I made sure to make my page layouts as clear and obvious to the users what everything is, while still maintaining a professional look for the app. This is evident in multiple aspects of my site, such as the admin home page, which shows clearly which buttons do what, while still looking as professional as possible, and not making my site be oversimplified and cluttered. This helps my site be accessible, as it means that users can be confident about what they are doing, even with little to no explanation on how to use the app. When I was coding the webpages, I made sure to adhere to HTML accessability standards, by using semantic tags and classes/ids, so people who use a screen reader don't constantly hear "div, div, div, div", but can tell what kind of section the page is. This helps add to the accessability of the site, as it means that people who use a screen reader can interact more confidently with my app, making it accessible to them. Overall, I considered different groups of people, and their different skills and weaknesses when navigating online web services, and did my best to account and accommodate for these, so my site can be used by all, regardless of any online disabilities they might have.


### Usability

While producing the web app, I made sure to make it as usable as possible. To do this, I kept in mind Nielsen's Usability Heuristics. For Example, I adhered to the heuristic of visibility throughout the design process. I did this by displaying multiple flash messages with common colours to indicate successes, errors/failures, or just information. This adheres to the Visibility heuristic, as it means that system updates are visible to the user, and it shows the user that the actions taken by the user are recognised by the system, so the user can be confident that the system has processed their data. This make the system more usable, as it makes the users more confident in the system, so they don't have to worry about whether or not the system has received their inputs. Another way I made my system more usable was by following the User Control and Freedom heuristic. I did this by having clearly labeled exit buttons, and checks on potentially dangerous actions, such as deleting users accounts.
